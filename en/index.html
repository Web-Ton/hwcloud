A Pluggable Multi-Agent AI Framework in Go

Every component is an interface — Model, Memory, Tools, Guards, Approver, Hooks, Observer — assembled by a 7-stage runtime. Three multi-agent modes (sub-agent delegation, transfer-to team, DAG orchestrate), ACP v1, layered governance, WASM plugins, and IM channels (Feishu / WeChat / WeCom). Agent is pure config; the runtime is the execution body.

Highlights

Pluggable interfaces

Model, Memory, Tools, Guards, Approver, Hooks, Observer — every component is an interface injected via Deps. Agent holds only config; the runtime wires the rest.

Three multi-agent modes

SubAgent (sync as-tool delegation), Team (transfer_to_* control handoff with loop detection), Orchestrate (LLM-planned DAG, parallel batches, auto-replan). Composable — an agent can be in a Team and a Plan step.

ACP v1 + IM channels

ACP v1 over stdio (VSCode/Zed/opencode). Plus three IM transports: Feishu (WebSocket cards, streaming, approval buttons), WeChat (ilinkai long-poll, one-shot replies), WeCom (native streaming). Process-level daemons.

7-stage runtime

guard.in → memory.fetch → prompt.build → model.call → guard.out → tool.execute → memory.append. Each stage emits observe events; policy + execution live inside tool.execute.

Layered governance

rules → safety → approval memory → human. First-match rules, read-only auto-allow, multi-key ALL-must-match memory, fail-closed human layer. Plan mode removes execution tools for safe exploration.

WASM plugins + sandbox

6 plugin types + cron-scheduled jobs, 28 host exports, wazero runtime, Rust PDK. OS-native sandbox (Linux bwrap / macOS Seatbelt) confines shell, file, and network.

Architecture at a glance

Agent is pure config; kernel.Runtime is a thin orchestrator running a 7-stage loop. The real subsystems — context, execution, governance, session, provider, eventbus — are independent top-level packages injected as interfaces, not kernel subdirectories.

Quick start

Prerequisites: Go 1.26+.

CLI

bash
go build -o hwcloud ./cmd/cli/

# Show version
./hwcloud -v

# ACP mode (stdio — for VSCode/Zed ACP plugins)
./hwcloud serve --acp

# REST mode (HTTP + SSE)
./hwcloud serve --port 8080

TUI

Prefer a terminal UI over raw CLI? hwcloud also ships a Rust ratatui TUI client (ACP over stdio) — build it and point it at any ACP backend.

bash
# Build the TUI (Rust + ratatui)
cd tui && cargo build --release

# Launch — defaults to 'hwcloud serve --acp' as backend
./target/release/hwcloud-tui

# Or point at any ACP backend
./target/release/hwcloud-tui --backend "opencode acp"

Configure

json
{
  "provider": {
    "openai": {
      "api_key": "sk-...",
      "models": ["gpt-4o"]
    }
  }
}

First run

  1. Build the CLI: go build -o hwcloud ./cmd/cli/
  2. Create ~/.hwcloud/settings.json with a provider (api_key + models).
  3. Optionally place AGENTS.md (working rules) and SOUL.md (persona) in ~/.hwcloud/profile/.
  4. Run ./hwcloud serve --acp for an ACP client (VSCode/Zed), or --port 8080 for REST + SSE.
  5. Toggle capabilities: --guard on, --approver on, --sandbox for OS-level confinement.
  6. Drop .wasm files in ~/.hwcloud/plugins/ — they auto-load by type.

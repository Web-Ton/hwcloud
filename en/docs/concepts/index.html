Core concepts

The vocabulary of hwcloud — Agent is pure config; the runtime is the execution body; everything pluggable is an interface.

#Configuration

Agent

Pure configuration: system prompts, model, guards, sub-agents, token budgets. No execution methods. Assembled into a Runtime via New(*agent.Agent, Deps).

pure-configno-execution
agent := agent.New(
    agent.WithModel(model),
    agent.WithSystemPrompts("You are..."),
    agent.WithSubAgents(...),
)
rt := kernel.New(agent, deps)

SubAgent

A child agent registered as a plain tool (named after the agent, e.g. "researcher"). The parent delegates a sub-task via tool call; the child runs a full agent loop with isolated memory (no SessionStore), filtered tools, inherited guard, then returns its FinalOutput. Synchronous — the parent blocks until the child finishes. NOT transfer_to_*.

as-toolsyncisolated-memory
// kernel/as_tool.go
// sa.Name → tool name (e.g. "researcher")
// parent calls researcher(task) → blocks
// child: own system prompt, no SessionStore
// returns FinalOutput string

AGENTS.md / SOUL.md

Static context profiles. AGENTS.md = working rules; SOUL.md = persona & limits. User-level (~/.hwcloud/profile/) + project-level ($(pwd)/) resolution; project overrides user.

staticprofileoverride
~/.hwcloud/profile/AGENTS.md   # user rules
./AGENTS.md                      # project rules (wins)

#Multi-agent

SubAgent (as-tool)

Single-agent delegation: a parent agent registers a child as a plain tool and calls it for a sub-task. The child runs a full agent loop with isolated memory (no SessionStore), filtered tools, inherited guard, then returns its output. Synchronous — parent blocks until child finishes. Tool name is the agent name, NOT transfer_to_*.

delegationsyncisolated
// kernel/as_tool.go + subagent.go
// parent calls researcher(task) → blocks
// child: own prompt, no SessionStore
// returns FinalOutput → tool result

Team (transfer_to_*)

Control-transfer handoff: agents run one at a time in a sequential chain. When an agent calls transfer_to_X (EndTurn tool), control passes to agent X — the original agent's turn ends. Each agent has private memory (tool calls/results) + shared team memory. Loop detection: ping-pong (A-B-A-B) and frequency (≥3 visits). transfer_to_* is Team-exclusive — not SubAgent, not Orchestrate.

handoffEndTurnprivate+shared-memoryloop-detect
// agent/team.go
// handoffTool: transfer_to_<name>, EndTurn=true
// teamRunner: sequential chain, maxHandoffs=10
// REST: POST /api/team/... (rest/team.go)

Orchestrate (DAG)

Plan-and-execute: an LLM Planner decomposes the goal into a DAG once, before execution. The Executor runs steps in topological order with parallel batches (errgroup, max 8). Runtime is deterministic — no LLM except auto-replan on failure (rebuilds the affected subtree) and step summarization. Each step has an isolated session; upstream results shared as summaries.

DAGparallelauto-replandeterministic-runtime
// orchestrate/orchestrate.go + executor.go
// Planner.Plan() → PlanDef (DAG)
// executor: Kahn topo sort + errgroup batches
// REST: /generate(SSE) /execute /replan

#Runtime

Runtime

The execution body. Runs the 7-stage loop, holds Deps-injected subsystems, manages tools/approver/memory per session. Created by kernel.New(agent, deps).

7-stageorchestratorDeps
// kernel/runtime.go
rt := kernel.New(agent, deps)
rt.RunStream(ctx, session, ...)

AgentContext

Assembled every turn 0 by context.Runtime.Build(): system prompts + recalled knowledge + working memory + compressed summary. Updated per-turn with new messages.

per-turnknowledge-recall
// context/provider.go
ac := rt.context.Build(session)
// system + skills + memory + working + summary

Session

Three modes: auto (tools execute immediately), manual (each non-readonly tool asks approval), plan (plan_create/plan_update before execution). Per-session state in SessionStore.

automanualplan
./hwcloud serve --acp
# mode set via /mode or session/set_mode
# default_mode in settings.json

#Governance

Policy

The layered engine: rules → safety → memory → human. rules = first-match glob; safety = read-only auto-allow; memory = multi-key ALL; human = fail-closed.

layeredEvaluate
// governance/policy.go
d, err := engine.Evaluate(ctx, call, def, session)
// Allow | Deny | Ask(→human)

ApprovalMemory

Two implementations: SessionApprovalMemory (in-process) and PersistentApprovalMemory (store-backed, survives restarts). Remember/Recall keyed by tool + args; shell uses multi-key (atoms + files).

sessionpersistentmulti-key
// governance/memory.go + persistent_memory.go
type ApprovalMemory interface {
    Remember(ctx, sessionID, key, Decision) error
    Recall(ctx, sessionID, key) (Decision, bool)
}

Decision

The policy verdict: Allow, Deny (with reason), or Ask (route to human). Carries ModifiedArgs so a human can approve with edited arguments.

AllowDenyAskModifiedArgs
type Decision struct {
    Action       ApprovalAction  // allow|deny|ask
    Reason       string
    ModifiedArgs json.RawMessage
}

#Memory & knowledge

Working memory

The recent message window, trimmed by token count. Budget = MaxWorkingTokens or 70% of the model's context window. Overflow trimmed from the bottom.

token-driven70%-window
// kernel/prepare.go
budget := workingTokenBudget()
return msgs[overflow:], ci, nil

Compressed memory

LLM-generated incremental summary in 8 sections (Claude Code format). Auto-triggered when working set overflows, or manually via /compact. Bounded by MaxCompressedTokens.

llm-summary8-sections/compact
// summarizer/llm.go
summary, err := compressor.Summarize(ctx, msgs)
// injected into prompt as compressed section

MemoryProvider

A separate durable knowledge layer — NOT message archiving. Stores preference/fact/lesson entries with vector + keyword recall. LLM extractor turns finished runs into knowledge (self-evolution). Pluggable: SQLite (vector) or OpenViking (remote).

preferencefactlessonvectorself-evolution
// context/provider.go
type MemoryProvider interface {
    Search(ctx, query) ([]Knowledge, error)
    Remember(ctx, Knowledge) error
}
// kinds: preference | fact | lesson

#Extension

WASM Plugin

6 types: agent:tools, agent:observers (agent-side); cli:settings, cli:commands, cli:observers, cli:http (CLI-side). Any can declare cron-scheduled jobs. wazero runtime, Rust PDK, 28 host exports.

wasm6-typescronwazero
// settings.json
{ "plugins": ["~/.hwcloud/plugins"] }
// scans *.wasm, loads by metadata type

MCP

Model Context Protocol client — imports external tools (browser, IaC, etc.) into the agent's tool set. Each tool call renders as a normal tool result.

external-toolsstdio/http
// settings.json
"mcp_servers": {
  "browser": { "command": "npx",
    "args": ["-y","@anthropic/mcp-server-browser-tools"] }
}

Hook / Observer

RunHooks: start/end callbacks sharing opaque state (OTEL spans nest, slog logs duration). Observer: enter/leave for each of the 7 stages — can abort the run.

RunHooksObserver7-stages
// observer.go
rt.observe(ctx, StageModelCall, "enter",
    map[string]any{"model": req.Model}, time.Time{}, nil)

IM channels

Three platforms via one channel.Channel interface. Feishu: WebSocket + Schema 2.0 interactive cards (collapsible panels, tool-call cards, approval buttons, /mode), patch-based streaming. WeChat: ilinkai HTTP long-poll, plain-text one-shot replies (no card API), CDN media. WeCom: WebSocket + native streaming (message grows in place), template_card approvals. Process-level daemon; --channel flag or POST /connect starts it.

feishuwechatwecomstreaming
./hwcloud serve --channel feishu
# QR scan → bot provisioned, creds saved
# process-level: frontend only triggers/observes
# /clear /mode (feishu) slash commands

Plan mode

One of three session modes (auto/manual/plan). In plan mode, execution tools (shell/write/terminal) are removed; only read-only tools + plan_create/exit_plan_mode remain. The agent explores and decomposes, then exits to execute. plan_update (mark step status) works in ALL modes. enter_plan_mode/exit_plan_mode switch the tool set.

read-onlyplan_createexit_plan_modecross-mode
// acp/server.go
enter_plan_mode → inject plan_create+exit
plan mode: shell/write removed, read-only kept
exit_plan_mode → restore previous mode

Process manager

Background shell processes that persist across turns. Each gets a dir (stdout.log/stderr.log/exit.code); output writes to disk (not pipes) so it survives parent exit. The model reads /proc-<pid>/stdout.log and checks exit.code across turns. Per-session; cleanup kills all on session end.

cross-turndisk-outputper-session
// process/manager.go
Create(cmd) → dir/<hex-id>/
SetPID(pid) → rename to proc-<pid>
model reads proc-<pid>/stdout.log

Sandbox

OS-native confinement for shell/file/network. Linux: bubblewrap (bwrap) — new mount namespace, system paths read-only, workspace writable, --die-with-parent; PID namespace intentionally NOT unshared (so the model can kill processes). macOS: sandbox-exec + Seatbelt profile. Windows: NYI (runs unconfined with warning). Network isolation optional (--sandbox + network:isolated).

bwrapseatbeltnamespacefail-open
./hwcloud serve --sandbox --port 8080
# bwrap: --ro-bind /usr, --bind /workspace
# --unshare-net (if network=isolated)
# bwrap missing → unconfined + warn
